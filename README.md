# rabbinatix

Rabbinatix on your machine and in CI: one package, one command, `rabbinatix <command>`. Node.js 20 or later, on
Linux, macOS and Windows: `npx -y rabbinatix --help`.

Fixed rules, the same answer every time, so it can block a merge or a deployment. It never calls an AI model, and none
of your code leaves the machine: each command's `--help` ends with exactly what it sends. Where a result needs
understanding, it prints the AI prompt to give your assistant instead. Which does what: the app's docs,
`/docs/assistant-or-cli`; every command: `/docs/rabbinatix-cli`.

| Command | What it does | Token scope |
|---|---|---|
| [`impact`](#rabbinatix-impact) | What a code change affects, in behaviour | `read` (`deploy` to `--store`) |
| [`status`](#rabbinatix-status) | Whether the code is in step with the map (anchors behind, gone, missing, unanchored routes) | `read` |
| [`test`](#rabbinatix-test) | Runs flows' test cases, simulated; `--affected` only those a change affects | `read` |
| [`scan`](#rabbinatix-scan) | Security issues in the repository, reported to Security checks → Code scan | `scan` with `--report` |
| [`deploy check` / `deploy record`](#rabbinatix-deploy) | Gate a release, then record it | `read` / `deploy` |
| [`generate`](#rabbinatix-generate) | The generated code of logic, as the Code panel downloads it; `--check` for CI | `read` |
| [`verify`](#rabbinatix-verify) | The Python, C#, Java, Go, Kotlin, Swift, Dart, PHP, Ruby or Rust build checked against recorded test runs | `read` |
| [`openapi pull` / `openapi diff`](#rabbinatix-openapi) | A system's OpenAPI file; a repo's spec against the map | `read` |
| [`mock`](#rabbinatix-mock) | A system's test server on your machine | `read` |
| [`relay`](#rabbinatix-relay) | Sends Test APIs' requests from your computer (no CORS) | none |
| [`watch import`](#rabbinatix-watch-import) | A HAR recording or trace file checked against the contracts | the watcher's key |
| [`watch listen`](#rabbinatix-watch-listen) | Calls from phone apps and OpenTelemetry checked as they happen | the watcher's key |

Connection, for every command: `--api`, else `RABBINATIX_API`, else `"api"` in `.rabbinatix/config.json`; the token
from `RABBINATIX_TOKEN` (or `--token-env <name>`), never from the config file. Exit codes: `0` done · `1` the check you
asked for failed (`--fail-on`, `--check`) · `2` an error.

## rabbinatix impact

What a code change affects, in behaviour. It reads your pull request's diff on the machine it runs on, finds the
Rabbinatix logic and API routes the changed code belongs to (directly or through its callers), and asks Rabbinatix
which flows, contracts and test cases that reaches.

Plan and design: `docs/04-roadmap/code-impact-plan.md` in the app repository.

### What leaves the machine

Only keys (`LOGIC-…`, `NODE-…`), revisions, function names, file paths, line numbers and API routes. Never code.
When nothing the change touches is on the map, nothing is sent at all: the answer is worked out locally.
`--dry-run` prints the exact request and sends nothing.

### How it finds the map

- **Anchors.** Comments the code panel and *Copy for my assistant* write into code:
  `// FDD:LOGIC-AUTH-LOGIN-001 r9 Sign in` above a function, `// FDD:NODE-AUTH-LOGIN-007 Find the user` above a
  step, and the first line of generated files (`// Generated by Rabbinatix · logic LOGIC-… v1.3.0 (r12)`). Any
  language works (`//`, `#`, `--` comments).
- **Callers (TypeScript and JavaScript).** A changed function without an anchor is followed back through the code
  that calls it (TypeScript's own *find references*), up to `--depth` calls, until an anchor or a route is reached.
  Each package is read with its nearest `tsconfig.json`.
- **Routes.** The routes of 28 web frameworks (the table below) are matched to the APIs on the map. Where a route names
  the function that handles it (`r.GET("/orders/:id", h.GetOrder)`, `resources :orders`, `[OrderController::class,
  'show']`), a changed line in that function counts as a change to the route, in whichever file the function is.
- **OpenAPI files.** Operations added, removed or changed (through `$ref`s) count as API changes; a removed or
  changed one may break its contracts.
- **Tests.** Changed test files, and test files that call the changed code, are listed as tests to run.
- Docs, lock files and build output are left out. Anything else that isn't on the map is listed as such, and the
  answer suggests running all tests.

### Languages

| | Logic comments and generated headers | Follows the code that calls a changed function | API routes in code | Test files |
|---|---|---|---|---|
| TypeScript, JavaScript | yes | yes | Express, NestJS, Fastify, Hono, Koa, Next.js (`app/…/route.ts`, `pages/api`) | `*.spec.ts`, `*.test.js`, `__tests__/` |
| C# | yes | no | ASP.NET controllers (`[Route]`, `[HttpGet]`…), minimal APIs (`MapGet`, `MapGroup`) | `*Tests.cs`, `*.Tests/` |
| Java, Kotlin | yes | no | Spring (`@RequestMapping`, `@GetMapping`…), JAX-RS (`@Path`, `@GET`…), Ktor (`route("/x") { get { } }`) | `src/test/`, `*Test.java`, `*IT.java` |
| Python | yes | no | FastAPI (`@app.get`, `APIRouter(prefix=…)`), Flask (`@app.route`, `Blueprint(url_prefix=…)`), Django (`urls.py` with `include()` prefixes, DRF routers) | `test_*.py`, `*_test.py`, `tests/` |
| Go | yes | no | net/http (`"GET /x/{id}"`), gorilla/mux, gin, echo, fiber (`Group`), chi (`Route`) | `*_test.go` |
| Ruby | yes | no | Rails (`config/routes.rb`: `resources`, `namespace`, `scope`, `get … to:`), Sinatra | `*_spec.rb`, `test/` |
| PHP | yes | no | Laravel (`Route::get`, `prefix()->group`, `apiResource`; `routes/api.php` under `/api`), Symfony `#[Route]` | `*Test.php`, `tests/` |
| Rust | yes | no | axum (`.route("/x", get(h))`), actix-web (`#[get]`, `web::resource`), Rocket | `tests/` |
| Swift | yes | no | Vapor (`app.get("orders", ":id")`, `grouped`, `use:`) | `*Tests.swift` |
| Dart | yes | no | shelf_router (`router.get`, `@Route.get`), Dart Frog (`routes/…/[id].dart`) | `*_test.dart` |
| Scala, C/C++, Elixir, Lua, SQL, and the rest of the 33 | yes (`//`, `#` or `--` comments) | no | no | `tests/` |
| OpenAPI files (YAML or JSON) | — | — | operations added, removed or changed | — |

Outside TypeScript and JavaScript, a changed line is on the map when it sits under a logic comment, in a generated
file, inside an API handler of the frameworks above, or in a function a route names as its handler. A changed helper
with none of those is listed as *not on the map*, and the answer suggests running all tests; adding the logic's
comments (the code panel of the logic editor shows them) closes that gap. Routes are read from the text: Django's
`include()` prefixes are followed, but a router mounted with a prefix in another file (axum `nest`, chi `Mount`,
Express `app.use('/api', router)`) isn't seen.

### Use

```sh
export RABBINATIX_API="https://<your functions host>/api/v1"   # Integrations → API & CI → Base URL
export RABBINATIX_TOKEN="cm_live_…"                             # Integrations → API tokens (read; deploy to --store)
npx -y rabbinatix impact --comment impact.md
```

| Option | |
|---|---|
| `--base <ref>` | the older side: a branch, tag or commit (default: the PR's target in GitHub Actions / GitLab CI, else origin's default branch) |
| `--head <ref>` | the newer side (default: this checkout, with what isn't committed yet). Read from a temporary `git worktree` when it isn't checked out here, removed afterwards |
| `--straight` | compare `--base` and `--head` directly, not from where they split |
| `<base>...<head>`, `<base>..<head>` | the same in git's words: three dots from where they split, two dots directly |
| `--run-by assistant` | say an AI assistant ran it (the report says *AI assistant, with the CLI*); Claude Code is found by its own `CLAUDECODE` variable |
| `--api <url>` | the API address (or `RABBINATIX_API`) |
| `--token-env <name>` | the variable holding the token (default `RABBINATIX_TOKEN`) |
| `--store` | keep the report in Rabbinatix (the Code impact page, a system's Code changes tab); prints its link |
| `--format md\|json` | what to print (default `md`) |
| `--out <file>` | also write the answer as JSON |
| `--comment <file>` | also write the Markdown, for a pull request comment |
| `--fail-on inform\|warn\|breaks\|critical` | `inform` (default) never fails; `warn` never fails but says so in the headline; `breaks` fails when a contract may break; `critical` also when a critical flow is affected |
| `--title`, `--url` | the change's title (default: the last commit's subject) and pull request address |
| `--tsconfig <file>` | read the code with this tsconfig instead of the nearest one |
| `--depth <n>` | how many callers back to follow (default 6, at most 12) |
| `--dry-run` | print the request, send nothing |

Exit codes: `0` done · `1` the `--fail-on` policy failed · `2` something went wrong (no token, git error, Rabbinatix
unreachable). Fetch the whole history in CI (`fetch-depth: 0`): the change is measured from the merge base.

Compare any two branches or commits (code-impact-compare-plan.md), none of them checked out:

```sh
npx -y rabbinatix impact --base main --head feature/login --store   # what the branch adds to main
npx -y rabbinatix impact v1.2.0..v1.3.0 --store                     # every difference between two releases
```

The report names both sides with their commits, and says it was checked against today's map.

### GitHub Actions

```yaml
name: code impact
on: pull_request
permissions: { contents: read, pull-requests: write }
jobs:
  impact:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }
      - uses: actions/setup-node@v4
        with: { node-version: '22' }
      - name: What this change affects
        env:
          RABBINATIX_TOKEN: ${{ secrets.RABBINATIX_TOKEN }}
          RABBINATIX_API: ${{ vars.RABBINATIX_API }}
          PR_TITLE: ${{ github.event.pull_request.title }}   # through env: a title is anyone's text
          PR_URL: ${{ github.event.pull_request.html_url }}
        run: npx -y rabbinatix impact --store --comment impact.md --title "$PR_TITLE" --url "$PR_URL"
      - name: Comment on the pull request
        env: { GH_TOKEN: "${{ github.token }}" }
        run: gh pr comment ${{ github.event.number }} --edit-last --body-file impact.md || gh pr comment ${{ github.event.number }} --body-file impact.md
```

### GitLab CI

```yaml
impact:
  image: node:22
  rules: [{ if: $CI_PIPELINE_SOURCE == "merge_request_event" }]
  variables: { GIT_DEPTH: 0 }
  script:
    - npx -y rabbinatix impact --store --comment impact.md --url "$CI_MERGE_REQUEST_PROJECT_URL/-/merge_requests/$CI_MERGE_REQUEST_IID"
  artifacts: { paths: [impact.md] }
```

Post `impact.md` as a merge request note with your usual tool (for example `glab mr note`).

### Cost

One API call per run (none when nothing is on the map). Re-running the same commit with the same change returns the
stored report instead of adding another one. The server keeps one index document and one reports document per
project; no scheduled jobs.

## rabbinatix mock

A system's test server on your machine. It loads the system's published APIs from Rabbinatix once (`GET /v1/mock`,
the `read` scope), then answers every call itself, exactly as the hosted test server does: the same example values,
`?__status=` / `X-Mock-Status`, `?__seed=` / `X-Mock-Seed`, `?__version=` / `X-Mock-Version`, and *Validate requests*.
Calls to it never reach Rabbinatix, so there is no limit on them.

```sh
export RABBINATIX_API="https://<your functions host>/api/v1"   # Integrations → API & CI → Base URL
export RABBINATIX_TOKEN="cm_live_…"                             # Integrations → API tokens (read)
npx -y rabbinatix mock --system auth-service                    # the system's id or name
curl http://127.0.0.1:4010/api/v2/users/42                      # the endpoint's path, no org/project/system ids
```

| Option | |
|---|---|
| `--system <id\|name>` | the system (the Test server page shows the command with its id) |
| `--port <n>` | the port (default `4010`; `0` picks a free one) |
| `--host <address>` | where it listens (default `127.0.0.1`; `0.0.0.0` for other machines or containers) |
| `--api <url>`, `--token-env <name>` | as for `impact` |
| `--save <file>` | also write what was loaded |
| `--from <file>` | answer from a saved file: no call, no token (commit it so CI tests use the same APIs every time) |
| `--quiet` | don't print each call |

Type `r` and Enter to load the system again after publishing (one call). Ctrl+C stops it. It allows calls from any
origin, so a frontend's dev server can call it. Exit codes: `0` stopped · `2` something went wrong (no token, system
not found, port in use, Rabbinatix unreachable).

## rabbinatix scan

Security issues in the repository where it runs: the files git tracks plus new ones it doesn't ignore.

```
npx -y rabbinatix scan                                  # print them (Markdown)
npx -y rabbinatix scan --report --fail-on high          # send them to Rabbinatix, fail the build on high or worse
```

What runs:

| Scanner | Finds | Needs |
|---|---|---|
| Built-in rules | secrets in known formats; passwords and keys in the code; eval, shell and SQL built from variables, TLS checks off, HTML from variables, weak hashes, unsafe deserialization, JWT mistakes; for phone apps: `Info.plist` App Transport Security, `AndroidManifest.xml` cleartext and debuggable, keys in Android resources, trust-all certificate and hostname checks (Swift, Kotlin/Java, Dart), tokens in UserDefaults / SharedPreferences | nothing |
| OSV | known vulnerabilities in pinned dependencies: package-lock, yarn.lock, pnpm-lock, requirements*.txt (`==`), poetry.lock, Pipfile.lock, go.sum, Gemfile.lock, Cargo.lock, composer.lock, packages.lock.json, gradle.lockfile, Gradle's libs.versions.toml, pubspec.lock (Dart, Flutter), Package.resolved (SwiftPM), Podfile.lock (CocoaPods: each pod's source repository, from the lock file or the CocoaPods CDN, checked in OSV's Swift data; Objective-C-only pods rarely have advisories there) | network to api.osv.dev and, for pods, cdn.cocoapods.org (only names and versions are sent); `--no-deps` skips it |
| Gitleaks | its secret rules | `gitleaks` on PATH (used when there; `--gitleaks` requires it, `--no-gitleaks` skips it) |
| Semgrep | its security rules: the repo's `.semgrep.yml` / `.semgrep/`, else `p/default` (`--semgrep-config`) | `semgrep` on PATH (same switches) |

Each issue is listed once (same file, line and kind: a tool's finding over the built-in one), worst first. Code rules
skip tests, fixtures, examples and comment lines; secret rules don't, but skip made-up values (`…EXAMPLE`, `ABCDEF…`).
`rabbinatix-ignore` in a comment skips a line.

`--report` sends the findings to `POST /v1/code-scan` (a token with the `scan` scope in `RABBINATIX_TOKEN`, the address
in `RABBINATIX_API`), 100 a call with `more` on all but the last, with the repo, branch and commit from git (or the CI's
variables). Only the findings leave the machine: file, line, a one-line snippet with secrets masked, rule and hints.
In Rabbinatix they sit next to the assistant's findings, marked as found by rabbinatix scan; each kind of scan resolves
only its own fixed findings. The answer lists which of the sent findings people dismissed; `--fail-on` leaves those out.

`--format json` / `--out file` give the full list (`findings`, `ran`, `notes`, `files`, and with `--report` what
Rabbinatix did). Exit codes: 0 done, 1 `--fail-on` matched, 2 an error.

## rabbinatix status

Whether the repository's code is in step with the map. It reads the `FDD:` anchors in every file
(`// FDD:LOGIC-AUTH-LOGIN-001 r9`, in each language's own comment) and the API routes the frameworks declare, then
asks Rabbinatix: anchors whose logic has a newer revision (*behind*), anchors whose logic is gone, logic with no
anchor in this repo (*missing*), and route files with no anchor (*unanchored*).

```sh
npx -y rabbinatix status --fail-on behind,gone
npx -y rabbinatix status --write-map      # rewrite .rabbinatix/code-map.json from the anchors
```

`--system <id>` limits *missing* to one system. Sends the anchors' keys and revisions with their file names and lines.

## rabbinatix test

Runs the flows' test cases, simulated, as Run does in the app: test data answers every call, nothing reaches the
network. Critical flows run first.

```sh
npx -y rabbinatix test --flow FLOW-CHECKOUT-001
npx -y rabbinatix test --affected impact.json   # the flows `rabbinatix impact --out impact.json` named
```

`--system <id>` runs a system's flows. `--fail-on failed` (default) · `critical` (only critical flows fail it) ·
`never`. At most 50 flows a call, a few calls a minute per token. Sends the flow keys and system IDs.

## rabbinatix deploy

```sh
npx -y rabbinatix deploy check  --system orders --version "$VERSION" --env prod   # exit 1 when blocked
./deploy.sh
npx -y rabbinatix deploy record --system orders --version "$VERSION" --env prod
```

`check` is Deployments' *Safe to deploy?*; when blocked it prints why and the AI prompt *Explain why this deployment is
blocked*. `record` needs a `deploy` token; an environment that asks for approval gets a promotion request instead.
Where an environment requires sign-off from affected teams (or a no-release period stops moves), `record` is refused
until they sign off; `--allow-missing-signoff "<why>"` moves it anyway and records the reason.

## rabbinatix generate

The code of logic, as the Code panel downloads it: TypeScript (formatted with Prettier, as the panel does), Python,
C#, Java, Go (one package per system, under `internal/fdd/`), Kotlin (one package per system, under `src/main/kotlin/`), Swift (one SwiftPM target
per system, under `Sources/`), Dart (one folder of libraries per system, under `lib/fdd/`), PHP (one namespace and folder per system, under `src/Fdd/`;
add the files to Composer's `autoload.files` or require the handler file), Ruby (one module and folder per system, under `lib/fdd/`;
`require_relative` the handler file) or Rust (one module per system, under `src/fdd/`; declare it as
`pub mod fdd { pub mod <system>; }`).

```sh
npx -y rabbinatix generate --logic LOGIC-AUTH-LOGIN-001 --language python
npx -y rabbinatix generate --system auth-service --check   # CI: exit 1 when a file is missing or older than its logic
npx -y rabbinatix generate --system auth-service --record  # also list it on the code panel's Exported tab
```

Nothing is recorded in Rabbinatix without `--record`. `--out-dir`, `--comments`. Sends the keys and the language
(with `--record`, each written file's path and sha256).

## rabbinatix verify

Builds the Python, C#, Java, Go, Kotlin, Swift, Dart, PHP, Ruby or Rust code of a logic on this machine and runs every step of its latest recorded test runs
through it: the same answers, calls and path, or the first difference. TypeScript is verified in the app. Needs
Python 3.10+, the .NET 8 SDK, JDK 21, Go 1.22+, Kotlin 1.9+ (kotlinc) with a JDK, Swift 5.9+, Dart 3+, PHP 8.1+ with mbstring, Ruby 3.1+ or Rust 1.70+ (rustc) for its language.

```sh
npx -y rabbinatix verify --logic LOGIC-AUTH-LOGIN-001 --language java
```

`--keep <dir>` keeps the built programs. Sends the logic's key and the language.

## rabbinatix openapi

```sh
npx -y rabbinatix openapi pull --system orders --out orders.yaml           # stamped with its newest release
npx -y rabbinatix openapi diff api/openapi.yaml --system orders --fail-on breaking
```

`pull` writes YAML for `.yml`/`.yaml`, else JSON; `--version` picks a release. `diff` sends only the file's
operations and schemas (no descriptions, servers or other text) and lists what changes against the map, with what
would break callers. `--fail-on breaking` (default) · `any` · `never`.

## rabbinatix relay

Sends Test APIs' requests from your computer, so the API needs no CORS headers and local or VPN addresses work.

```sh
npx -y rabbinatix relay          # shows a code; then Test APIs → Send through → This computer
```

Listens on `127.0.0.1:4011` only (`--port`), answers only Rabbinatix's pages (`--origin` adds one) and only with the
code it shows, which changes on every start. Only http(s), bodies up to 10 MB, 30 s per request. Sends nothing to
Rabbinatix.

## rabbinatix watch import

A HAR recording (the browser's Network tab → *Save all as HAR*, or a proxy's) checked against the contracts, as the
downloaded contract watcher checks live calls, and reported the same way.

```sh
npx -y rabbinatix watch import session.har --watcher src/dev/rabbinatix-watch.js
```

It also reads OpenTelemetry traces, JSON or protobuf (gzipped or not): one OTLP request, or a collector's file export
(`format: json` or `format: proto`). Client spans are the calls; they hold no bodies, so only statuses, undeclared calls and (when recorded) request headers are checked.

`--no-share` only prints. `--fail-on breaking|warning|never`. Sends, per finding, the API, what was expected and what
was found, and how often; per call, the API, status and timing. Never the values seen.

## rabbinatix watch listen

Calls checked while an app runs. Listens on `127.0.0.1:4012` (`--port`, `--host 0.0.0.0` for phones on the network,
which then need the code it shows) for:

- `POST /calls`: the phone SDKs in the watcher download (`phone/`: OkHttp, URLSession, Dio, package:http, React
  Native's fetch and XMLHttpRequest), one observed call each, with bodies;
- `POST /v1/traces`: OTLP/HTTP from any OpenTelemetry exporter, protobuf (the default) or JSON, gzipped or not
  (`OTEL_EXPORTER_OTLP_ENDPOINT=http://127.0.0.1:4012`).

```sh
npx -y rabbinatix watch listen --watcher rabbinatix-watch.js
```

Each new finding prints as it happens; findings are reported in the watcher's batches (about every 10 s); Ctrl+C
prints the summary. Same `--no-share`, `--fail-on` and what it sends as `watch import`.

## Working on the CLI

```sh
npm install
npm run check     # typecheck, tests, build: dist/rabbinatix.js and dist/harness/ for verify
```

| Path | What |
|---|---|
| `src/` | the commands: `src/bin/rabbinatix.ts` is the entry, one `*-cli.ts` per command, `src/scan/` the security scan |
| `src/from-app/` | code shared with the Rabbinatix app (languages, the test server's answer, the watcher's checks, run comparison), the same files as the app's `src/app` |
| `harness/` | the programs `verify` builds the generated code with, one per language |
| `test/` | vitest; `test/fixtures/api` holds recorded `/v1/generate` and `/v1/runs` answers, so no test needs the app or a network |
| `scripts/` | `sync-from-app.mjs` and `record-fixtures.spec.ts` (below) |

The CLI holds **no code generator**: `generate` and `verify` get their files from the API, and `test/bundle.spec.ts`
fails if a generator file is ever bundled in.

**Keeping in step with the app** (both need the app's folder, `APP_DIR`):

- `APP_DIR=../app npm run sync` lists the shared files that differ; `npm run sync -- --write` copies the app's
  versions in. Then run `npm run typecheck`: a new import in an app file shows up as a missing module. Files that start
  with `TYPE STAND-IN` are this repo's own (only the types of a much larger app file) and are left alone.
- `APP_DIR=../app npm run record-fixtures` records the API answers again, after `/v1/generate` or `/v1/runs` changes.
